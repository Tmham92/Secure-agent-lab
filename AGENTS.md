# Repository work

After finishing each implementation phase, extend `DEMO_GUIDE.md` in the repository root.
For every new or changed demonstration, document its purpose, learning goal, security
issue, prerequisites, exact commands, actors/trust boundaries, sequence, expected output,
actual effects, saved evidence, cleanup/recovery and limitations. Update the phase/status
matrix and clearly separate verified behavior from pending validation. Keep earlier
examples accurate when later phases change shared code. Update README.md and plan.md too.

Keep demonstrations synthetic. Never commit credentials or ignored runtime artifacts.
